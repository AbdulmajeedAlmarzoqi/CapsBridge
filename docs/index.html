CapsBridge

Caps Lock as your screen reader's key, in Windows on your Mac.

Download for Mac Source on GitHub العربية

Free and open source. For Apple silicon Macs with macOS 26 or later, and Windows in VMPal.

The problem

On a laptop keyboard, most screen reader users make Caps Lock their modifier key: hold it, press T, and NVDA reads the window's title. JAWS and Narrator work the same way.

Run Windows in a virtual machine on a Mac and that stops working. macOS tells apps that Caps Lock changed state, never that it was pressed and released, so Windows can't see you holding it. You press Caps Lock with another key, and the screen reader hears only the other key.

What CapsBridge does

CapsBridge sends Caps Lock to Windows as a key that really goes down and comes up. Your screen reader gets the Caps Lock it expects: hold it for commands, press it twice quickly to turn Caps Lock on or off.

It does that only while your Windows virtual machine is in front. Everywhere else on the Mac, Caps Lock stays exactly what it was, for VoiceOver too.

Setting it up

  1. Download CapsBridge, unzip it and open it. Let it move itself to the Applications folder.
  2. Press Set Up.
  3. When it asks, let it restart Windows. Save your work in Windows first.

CapsBridge finds VMPal and your Windows virtual machine by itself, installs a small helper on the Mac, teaches Windows the key, and turns on Caps Lock in NVDA if NVDA is there and it was off. Every step is spoken by VoiceOver as it happens.

After that you don't need the app open. Open it again whenever you want to check: it lists what it looked at, says what's fine and what isn't, and its button fixes what isn't.

Removing it

Press Remove CapsBridge… in the app. It takes its key mapping out of Windows, puts NVDA's setting back the way it found it, removes its helper from the Mac, and offers to move the app to the Trash. Nothing else on either side is touched.

Questions

Does it change Caps Lock on my Mac?

No. The mapping is on only while the Windows virtual machine's window is in front, and it's never saved. In every other app Caps Lock behaves as always.

Which screen readers does it work with?

It's tested with NVDA. JAWS in its laptop layout and Narrator use Caps Lock the same way and get the same real key from Windows, so they should work too, though they haven't been tested yet.

What does it change in Windows?

One entry in the registry's Scancode Map, which turns the F18 key the Mac sends into Caps Lock, and NVDA's Caps Lock setting if it was off. The full list is in the project's readme.

What if I take Windows back to a snapshot?

An older snapshot may not have the key mapping. Open CapsBridge: it notices, and its button reads Fix.

Does it work with other virtual machine apps?

Only VMPal for now.

How do I get updates?

CapsBridge takes care of it. It checks once a day, shows what's new in your language, and installs the update when you choose to. Every update is signed, and only one from the same developer is installed.

Is it safe to open?

The app is signed with an Apple Developer ID and notarized by Apple, and all of its code is public.
